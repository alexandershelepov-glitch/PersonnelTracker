# Учёт личного состава — PersonnelTracker

Запустите `start_mac.command` двойным щелчком. При первом запуске нужен интернет для установки PySide6. Если запуск завершился ошибкой, полный текст сохранён в `data/logs/launch.log`.

## Текущее состояние

Ветка `main` содержит принятую версию v0.6. Разработка v0.7 ведётся отдельно и начинается с защиты данных: встроенных резервных копий и безопасного восстановления.

Приложение использует одну локальную SQLite-базу `data/personnel.db`. Фотографии работников находятся в `data/photos/`, а в базе хранятся относительные пути к ним.

## Резервные копии — v0.7.1

На странице **«Сервис»** доступны команды:

- **«Создать резервную копию»** — формирует ZIP-архив с согласованным снимком SQLite и всеми фотографиями;
- **«Восстановить из копии»** — сначала проверяет ZIP, целостность SQLite, обязательные таблицы и версию схемы, и только после этого заменяет рабочие данные;
- перед каждым восстановлением автоматически создаётся отдельная страховочная копия текущего состояния;
- один раз в день при запуске создаётся автоматическая локальная копия; хранятся семь последних автоматических копий.

По умолчанию автоматические и страховочные копии находятся в `data/backups/`. Ручную копию можно сохранить в выбранное пользователем место.

Резервный ZIP содержит:

- `manifest.json` — сведения о формате, времени создания и версии схемы;
- `database/personnel.db` — согласованный SQLite-снимок;
- `photos/` — фотографии работников.

Приложение не использует резервный ZIP как рабочую базу. В дальнейшем Google Drive должен применяться как место хранения готовых резервных копий, а рабочая SQLite-база останется локальной.

## Миграции данных

Миграции выполняются автоматически при запуске и не должны удалять работников, фотографии, проверки, обучение, оружие и события. Текущая версия схемы хранится в таблице `settings`.

## Демо-данные

Для пустой тестовой базы в меню и на странице «Сервис» доступна команда **«Добавить демо-данные»**. Повторное добавление поверх существующих данных запрещено.

## Тесты

```bash
source .venv/bin/activate
python -m unittest discover -s tests -v
```

Для v0.7.1 добавлен отдельный набор `tests/test_backup.py`, который проверяет создание копии, возврат базы и фотографий к снимку, отказ от повреждённого ZIP, защиту от небезопасных путей и ежедневное автокопирование с ограничением количества копий.

GUI smoke-тест запускается отдельно:

```bash
.venv/bin/python tests/smoke_gui.py
```

## Ограничения текущего этапа

В v0.7.1 ещё нет CSV-импорта/экспорта и загрузки резервных копий в Google Drive. Эти функции относятся к следующим этапам v0.7.
