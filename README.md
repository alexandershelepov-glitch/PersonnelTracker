# Учёт личного состава — PersonnelTracker

Запустите `start_mac.command` двойным щелчком. При первом запуске нужен интернет для установки PySide6. Если запуск завершился ошибкой, полный текст сохранён в `data/logs/launch.log`.

## Текущее состояние

Ветка `main` содержит принятую v0.7: безопасные резервные копии и восстановление, CSV-обмен и полностью автономную настраиваемую локальную папку резервных копий.

Разработка v0.8 ведётся в `feature/v0.8-history`.

Приложение использует одну локальную SQLite-базу `data/personnel.db`. Фотографии работников находятся в `data/photos/`. Для обычной работы интернет не требуется.

## v0.7

- v0.7.1 — безопасные ZIP backup/restore базы и фотографий;
- v0.7.2 — CSV import/export с предпросмотром и защитой от дублей;
- v0.7.3 — настраиваемая локальная папка резервных копий без обязательного облака.

Google Drive не является частью рабочего механизма приложения. Готовые ZIP-копии при необходимости можно вручную перенести на внешний или облачный носитель.

## История штатных назначений — v0.8.1

При первом запуске v0.8 создаётся отдельный журнал `staff_assignments` и фиксируется дата начала исторического учёта.

Ключевой принцип: приложение **не выдумывает прошлую историю**. Уже занятые на момент обновления штатные единицы записываются как начальное состояние только с момента включения v0.8. Более ранний срез намеренно недоступен.

После включения истории SQLite-триггеры автоматически фиксируют:

- назначение работника на штатную единицу;
- освобождение штатной единицы;
- перевод на другую ШЕ через обычные действия интерфейса;
- изменение номера ШЕ, подразделения, отделения, группы или должности при занятой единице;
- освобождение ШЕ при переводе работника в архив/увольнении.

Историческая запись хранит снимок ФИО, табельного номера и реквизитов штатной единицы на момент назначения. Поэтому последующее изменение текущей ШДС не переписывает уже завершённые периоды.

На странице **«Сервис»** доступны:

- **«История назначений»** — полный журнал периодов с фильтром по работнику;
- **«Срез назначений на дату»** — кто занимал какую штатную единицу на конец выбранного дня.

Если в базе обнаруживается несовместимая экспериментальная таблица `staff_assignments`, она не удаляется. Она переименовывается в `staff_assignments_legacy_...`, после чего v0.8 создаёт новую совместимую структуру и честную стартовую точку.

## Состояние личного состава на дату — v0.8.2

На странице **«Сервис»** добавлен блок **«Состояние личного состава на дату — v0.8.2»**.

Срез объединяет уже существующие данные приложения, не создавая второго журнала отсутствий:

1. Штатное назначение на выбранный день берётся из истории `staff_assignments`.
2. Событие из `events` имеет приоритет над графиком: отпуск, больничный, командировка, ММ, другой объект, подготовка и другие зарегистрированные категории.
3. Если события нет, рассчитывается график работника:
   - `1/3` — от указанной опорной рабочей смены;
   - `5/2` — понедельник–пятница работа, суббота–воскресенье выходной;
   - `Не задан` — строка помечается как **«Требует проверки»**, а не считается автоматически доступной.
4. Действующие работники без штатной единицы не пропадают из среза и показываются как **«ВНЕ ШДС»**.
5. По каждой строке выводятся ШЕ, подразделение, отделение, группа, должность, ФИО, табельный номер, график, статус, место/объект и итоговая доступность.
6. Есть фильтр **Все / Доступен / Недоступен / Требует проверки** и итоговые счётчики.

Срез доступен только начиная с фактической даты старта v0.8 и не строится на будущую дату.

Важно: v0.8.2 отвечает на кадровый вопрос **«где числился и в каком состоянии был работник на выбранную дату»**. Полная историческая штатная численность и исторические вакансии пока не рассчитываются, потому что история создания/удаления самих штатных единиц ещё не ведётся. Приложение не подменяет этот пробел текущей ШДС.

## Демо-данные

Для пустой тестовой базы в меню и на странице «Сервис» доступна команда **«Добавить демо-данные»**. Повторное добавление поверх существующих данных запрещено.

## Тесты

```bash
source .venv/bin/activate
python -m unittest discover -s tests -v
```

Существующие тесты v0.7 проверяют backup/restore, CSV и пользовательскую папку резервных копий.

Для v0.8.1 используются `tests/test_assignment_history.py` и `tests/test_assignment_history_compat.py`: baseline, назначение/освобождение, изменение ШЕ, архивирование, запрет выдуманной истории и безопасное сохранение несовместимой старой таблицы.

Для v0.8.2 добавлен `tests/test_temporal_snapshot.py`: назначенные и неназначенные работники, приоритет события, расчёт `5/2`, расчёт `1/3`, неизвестный график и баланс итоговых счётчиков.

GUI smoke-тест запускается отдельно:

```bash
.venv/bin/python tests/smoke_gui.py
```
