# Учёт личного состава — PersonnelTracker

Запустите `start_mac.command` двойным щелчком. При первом запуске нужен интернет для установки PySide6. Если запуск завершился ошибкой, полный текст сохранён в `data/logs/launch.log`.

## Текущее состояние

Ветка `main` содержит принятую v0.7: безопасные резервные копии и восстановление, CSV-обмен и полностью автономную настраиваемую локальную папку резервных копий.

Разработка v0.8 ведётся в `feature/v0.8-history`. Первый этап — честная история штатных назначений и просмотр состояния назначений на выбранную дату.

Приложение использует одну локальную SQLite-базу `data/personnel.db`. Фотографии работников находятся в `data/photos/`. Для обычной работы интернет не требуется.

## Резервные копии — v0.7.1

На странице **«Сервис»** доступны создание и восстановление ZIP-копий. Копия включает согласованный снимок SQLite и фотографии работников. Перед восстановлением автоматически создаётся страховочная копия текущего состояния. Один раз в день при запуске создаётся автоматическая копия; хранятся семь последних автоматических копий.

## CSV — v0.7.2

Импорт CSV сначала показывает предпросмотр со статусами **«Готово»**, **«Проверить»** и **«Ошибка»**. Дубликаты по табельному номеру блокируются, а перед фактическим импортом создаётся `pre-import` копия. Импорт не занимает штатные единицы автоматически. Экспорт формирует Excel-совместимый CSV с действующим личным составом.

## Локальная папка резервных копий — v0.7.3

На странице **«Сервис»** можно выбрать отдельную локальную папку для автоматических и страховочных ZIP-копий. Рабочая база остаётся локальной и не зависит от облака. Если выбранная папка временно недоступна, приложение продолжает работать и предлагает выбрать другую.

Google Drive не является частью рабочего механизма приложения. Готовые ZIP-копии при необходимости можно вручную перенести на внешний или облачный носитель.

## История штатных назначений — v0.8.1

При первом запуске v0.8 создаётся отдельный журнал `staff_assignments` и фиксируется дата начала исторического учёта.

Ключевой принцип: приложение **не выдумывает прошлую историю**. Уже занятые на момент обновления штатные единицы записываются как начальное состояние только с момента включения v0.8. Более ранний срез намеренно недоступен.

После включения истории SQLite-триггеры автоматически фиксируют:

- назначение работника на штатную единицу;
- освобождение штатной единицы;
- перевод на другую ШЕ через обычные действия интерфейса;
- изменение номера ШЕ, подразделения, отделения, группы или должности при занятой единице;
- освобождение ШЕ при переводе работника в архив/увольнении.

Историческая запись хранит снимок ФИО, табельного номера и реквизитов штатной единицы на момент назначения. Поэтому последующее изменение текущей ШДС не переписывает уже завершённые периоды.

На странице **«Сервис»** появляется блок **«История штатных назначений — v0.8»** с двумя командами:

- **«История назначений»** — полный журнал периодов с фильтром по работнику;
- **«Срез назначений на дату»** — показывает, кто занимал какую штатную единицу на конец выбранного дня.

Срез разрешён только начиная с даты фактического старта исторического учёта и не строится на будущую дату.

История установлена отдельным модулем поверх проверенной v0.7. Если пользователь восстанавливает старую v0.7 резервную копию, модуль автоматически создаёт новый журнал и новую честную точку начала истории сразу после восстановления.

## Демо-данные

Для пустой тестовой базы в меню и на странице «Сервис» доступна команда **«Добавить демо-данные»**. Повторное добавление поверх существующих данных запрещено.

## Тесты

```bash
source .venv/bin/activate
python -m unittest discover -s tests -v
```

Существующие тесты v0.7 проверяют backup/restore, CSV и пользовательскую папку резервных копий.

Для v0.8.1 добавлен `tests/test_assignment_history.py`: стартовый baseline, автоматическая запись назначения и освобождения, разделение периода при изменении ШЕ, закрытие назначения при архивировании и запрет выдуманного среза до начала учёта.

GUI smoke-тест запускается отдельно:

```bash
.venv/bin/python tests/smoke_gui.py
```

## Дальнейший план v0.8

После проверки v0.8.1 на реальном интерфейсе следующий этап — расширение временной логики: календарное представление, работа с отсутствиями/отпусками во времени и более полный кадровый срез на дату.
