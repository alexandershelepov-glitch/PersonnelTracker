# Учёт личного состава — PersonnelTracker

Локальное desktop-приложение для учёта личного состава, штатной структуры, назначений, отсутствий, мероприятий и контрольных дат.

Текущая версия: **v1.0.0**.

## Основные возможности

- штатно-должностная структура с занятыми и вакантными штатными единицами;
- карточки работников и текущее назначение на ШЕ;
- история штатных назначений без перезаписи прошлых периодов;
- отсутствия, мероприятия и занятость с диапазонами дат;
- экран «Сегодня» с оперативным состоянием личного состава;
- планирование по календарю и списку;
- ручное и полуавтоматическое формирование команды;
- состояние личного состава и штатный срез на выбранную дату;
- рабочие отчёты: личный состав, штатная расстановка, состояние на дату, события и привлечение, история назначений;
- копирование табличных данных и CSV-выгрузка отчётов;
- CSV-обмен данными;
- ZIP backup/restore базы и фотографий с защитной копией перед восстановлением;
- настраиваемая локальная папка резервных копий;
- светлая/тёмная тема и современный интерфейс;
- сворачиваемая боковая навигация с сохранением выбранного состояния;
- standalone-сборка macOS.

## Принципы данных

Штатная единица остаётся основным источником организационных атрибутов назначения: подразделения, отделения/группы и должности.

История назначений хранит снимок данных на момент периода назначения. Последующее изменение текущей ШДС не должно переписывать завершённые исторические периоды.

Приложение не восстанавливает выдуманную прошлую историю. Исторические данные доступны только с момента фактического начала их ведения в базе.

Состояние на дату объединяет штатное назначение, зарегистрированные события и график работника. Событие имеет приоритет над графиком. Для графика `5/2` рабочими считаются понедельник–пятница; для `1/3` используется заданная опорная смена; незаданный график помечается как требующий проверки.

## Хранение данных

При запуске из исходников используется база:

```text
data/personnel.db
```

В standalone macOS-приложении рабочая база хранится отдельно:

```text
~/Library/Application Support/PersonnelTracker/data/personnel.db
```

Эти две базы автоматически друг с другом не синхронизируются.

Фотографии работников хранятся рядом с рабочими данными приложения. Для обычной работы интернет не требуется.

## Запуск из исходников на macOS

Основной запуск:

```bash
./start_mac.command
```

Либо через виртуальное окружение проекта.

## Тесты

Полный регрессионный прогон в headless-режиме Qt:

```bash
QT_QPA_PLATFORM_PLUGIN_PATH=/tmp/qttest/platforms \
QT_QPA_PLATFORM=offscreen \
.venv/bin/python -B -m unittest discover -s tests -p 'test_*.py' -v
```

GUI smoke-тесты запускаются отдельно при необходимости.

## Сборка standalone macOS

```bash
zsh build_macos.sh
```

Готовое приложение появляется в:

```text
dist/PersonnelTracker.app
```

Запуск:

```bash
open dist/PersonnelTracker.app
```

Сборка использует локальную ad-hoc подпись и предназначена для текущего локального рабочего сценария. Нотаризация Apple в v1.0.0 не выполняется.

## Резервное копирование

В приложении доступны ручное создание ZIP-копии и восстановление из ранее созданного архива. Перед заменой текущей базы при восстановлении создаётся защитная копия существующего состояния.

Google Drive не является обязательной частью рабочего механизма приложения. Готовые архивы при необходимости можно самостоятельно переносить на внешний или облачный носитель.

## Известное ограничение исторического учёта

v1.0.0 хранит историю назначений работников, однако не ведёт полноценную историю создания и удаления самих штатных единиц. Поэтому приложение не подменяет отсутствующую историю структуры текущей ШДС и не рассчитывает выдуманную историческую штатную численность или вакансии за период до начала соответствующего учёта.

## План после v1.0 — настраиваемое рабочее пространство

Следующий этап должен развивать пользовательскую настройку интерфейса без изменения кадровых данных и бизнес-логики:

1. **Перетаскиваемые колонки таблиц** — изменение порядка колонок мышью, сохранение порядка, ширины и видимости, команда сброса расположения.
2. **Настраиваемый порядок кнопок панелей** — отдельный режим «Настроить панель» с перестановкой и скрытием кнопок без случайного drag-and-drop в обычной работе.
3. **Настраиваемая компоновка карточек** — перестановка крупных логических блоков карточки работника при сохранении стабильной структуры полей внутри блоков.
4. **Dock-навигация** — развитие уже реализованной сворачиваемой боковой панели до варианта с выбором расположения слева, справа или снизу и сохранением пользовательской настройки.

Настройки интерфейса должны храниться локально и не менять кадровые записи, историю назначений или другие рабочие данные.
